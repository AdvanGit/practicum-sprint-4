##### Мотивация:
Мониторинг нужно добавить, потому что:
- **Улучшение видимости и повышение безопасности системы.** Видимость означает, что вы можете получить полное представление о работе системы. Чем выше видимость, тем проще обеспечить безопасность.
- **Более быстрое решение проблем и повышение надёжности системы.** С помощью инструментов наблюдения команда может быстрее определить корень проблемы. Следовательно, так её проще устранить и предотвратить в будущем.
- **Повышение быстродействия системы и распределение ресурсов.** С помощью инструментов наблюдения можно выявлять узкие места. Это помогает оптимизировать производительность — вы можете проанализировать, как система работает под разными нагрузками.
- **Ускорение рабочего процесса и DevOps.** Наблюдаемость способствует оптимизации процессов и сокращению количества ошибок. А это, в свою очередь, помогает ускорить рабочий процесс и улучшить взаимодействие между командами.
- **Ценные бизнес-инсайты.** Когда данные, которые вы собираете благодаря наблюдаемости системы, накапливаются, они могут привести вас к бизнес-инсайтам. Они помогут вам принимать стратегические решения более обоснованно.
- **Повышение удовлетворённости пользователей.** Своевременное решение проблем, которые связаны с производительностью и функциональностью приложения, улучшает пользовательский опыт.

##### Выбор подхода к мониторингу:
- Метод **USE** лучше всего работает с ресурсами, производительность которых снижается при интенсивном использовании. Что особенно актуально для MES Api.
- **Четыре золотых сигнала** больше ориентирован на работу с Api для клиентов, например CRM Api  и Shop Api. Он позволит мониторить задержки, трафик, ошибки и насыщенность.
- **RED** Так же можно использовать для всех Api сервисов, которые работают с запросами пользователей. Его метрики позволят отслеживать пиковый трафик, что будет полезно для верного распределения ресурсов.

##### План действий:

##### **1. Определение ключевых метрик для мониторинга**
- **Производительность системы:**
    - Время отклика MES (особенно при расчёте стоимости изделия).
    - Время загрузки дашборда заказов в MES.
    - Загрузка CPU, памяти, дискового I/O серверов MES и CRM.
- **Надёжность и доступность:**
    - Доступность API для внешних партнёров (uptime, ошибки 5xx).
    - Статус очередей RabbitMQ (количество сообщений, задержки).
- **Бизнес-метрики:**
    - Количество заказов в разных статусах (новые, в работе, просроченные).
    - Среднее время выполнения заказа (от создания до отгрузки).
    - Количество жалоб клиентов (B2C и B2B).

##### **2. Инструментарий для сбора и визуализации метрик**

- **Инфраструктурный мониторинг:** Prometheus + Grafana (для сбора и отображения метрик серверов, очередей, API).
- **Логи и трейсинг:** ELK Stack (Elasticsearch, Logstash, Kibana) и OpenTelemetry + Jaeger для анализа ошибок.
- **Бизнес-аналитика:** Дашборды в Grafana .
##### **3. Настройка алертинга**
- Автоматические оповещения при:
    - Задержках в расчёте стоимости (> 5 минут).
    - Очереди RabbitMQ переполнены (более N сообщений).
    - Ошибки API (например, >1% 5xx-ответов).
    - Рост количества заказов в статусе "просрочено".
